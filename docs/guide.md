# OpenCode Zen Rotator

Небольшая штука для бесплатных моделей OpenCode Zen.

Когда Zen отвечает `429 Rate limit exceeded`, программа пробует отправить тот же
запрос через другой адрес. В список можно добавить обычный интернет с машины
и свои прокси. Другие провайдеры и адреса идут напрямую, минуя ротацию.

Это не безлимит и не гарантия новой квоты. Если лимит есть на всех адресах,
придётся подождать. Используйте свои прокси и соблюдайте правила сервиса.

## Что нужно

- Linux.
- Python 3.10 или новее, вместе с `venv` и `pip`.
- Установленный OpenCode. Проверено с OpenCode 2.1.0.
- Хотя бы один маршрут: напрямую или через прокси.

Для автоматического запуска нужен systemd. Без него тоже можно, но запускать
программу придётся вручную. Windows и macOS установщик пока не поддерживает.

## Установка

Скачайте этот репозиторий, откройте его папку и выполните:

```bash
python3 install.py
```

Установщик спросит:

1. Какой порт использовать. Обычно можно оставить предложенный.
2. Добавлять ли прямое подключение.
3. Какие прокси добавить. Ввод скрыт, пустая строка завершает список.
4. Нужен ли сервис, чтобы всё запускалось автоматически.
5. Сделать ли алиас, чтобы вместо новой команды писать обычное `opencode`.
6. Проверить ли результат через `opencode run`.

Если OpenCode не нашёлся, укажите путь сами:

```bash
python3 install.py --opencode /путь/к/opencode
```

Пароли в адресе прокси с символами `@`, `:`, `/` нужно записывать в URL-формате:
например, `@` заменяется на `%40`. Настоящие данные остаются только на вашей машине.

Установщик создаёт своё Python-окружение. Он не меняет основной `opencode.json`
и не использует окружения от других проектов. Если одноимённый плагин, сервис
или команда уже существуют, он остановится, а не затрёт их.

## Как пользоваться

Без алиаса:

```bash
~/.local/bin/opencode-zen
```

С алиасом откройте новый терминал и запускайте как обычно:

```bash
opencode
```

Выбирайте модели встроенного провайдера, например
`opencode/deepseek-v4.1-flash-free`. Наличие конкретной модели зависит от каталога Zen.

Короткая проверка:

```bash
~/.local/bin/opencode-zen run \
  --model opencode/deepseek-v4.1-flash-free \
  'Reply only with OK.'
```

Обычный запуск и `run` открывают отдельный сервер OpenCode, чтобы тот загрузил
плагин. Уже запущенные сессии нужно перезапустить. Другие команды, например
`auth` и `models`, передаются OpenCode без лишних флагов.

## Что происходит внутри

```text
OpenCode → локальная программа → напрямую или через ваш прокси → Zen
```

Плагин перенаправляет только модели `opencode/*-free`. Локальная программа
сначала использует текущий рабочий адрес. Если пришёл `429`, она ставит его
на паузу и пробует следующий. При сетевой ошибке тоже пробует другой адрес.

На один запрос каждый доступный адрес проверяется максимум один раз. Если
везде лимит, возвращается `429` с временем ожидания. Во время паузы запросы
на этот адрес не отправляются. Обычно пауза берётся из `Retry-After`; если
такого заголовка нет, это 60 секунд. Максимум — час.

Когда ответ уже начал идти, повторов нет. Поэтому не должно быть двух копий
ответа из-за переключения. Сообщение Zen о дневном лимите также распознаётся,
если оно пришло отдельным обычным ответом `200` до начала потока. Ошибки,
которые появляются уже внутри потока, автоматически не переключаются.

Прямой маршрут — такой же участник списка, как прокси. У него тоже может быть
лимит. Остальные провайдеры и адреса идут напрямую, минуя ротацию.

## Счётчики

```bash
curl -s http://127.0.0.1:18998/health
```

Если выбрали другой порт, замените `18998`.

- `rotations_429` — сколько переключений реально сделано из-за HTTP `429`.
- `rate_limits_429` — сколько ответов HTTP `429` получено всего.
- `daily_free_limits` — сколько сообщений о дневном лимите бесплатных запросов получено.
- `retries` — все повторы, в том числе из-за сетевых ошибок.
- `requests` — количество попыток для каждого адреса в порядке списка.
- `current` — номер текущего маршрута, начиная с нуля.
- `active` — сколько запросов ещё выполняются.
- `cooldown_seconds` — сколько осталось ждать для каждого адреса.

Пароли и адреса прокси здесь не показываются. Счётчики хранятся в памяти
и обнуляются после перезапуска.

## Проверка, обновление и удаление

```bash
python3 install.py doctor
python3 install.py update
python3 install.py uninstall
```

Перед обновлением скачайте свежую версию репозитория. Повторная установка не
добавляет второй алиас. Перед перезаписью своих файлов установщик сохраняет
копии. Для обновления создаётся новое Python-окружение, чтобы не менять
зависимости работающей версии.

Обновление и удаление останавливаются, если есть активные запросы. На время
обновления лучше не отправлять новые запросы: перезапуск сервиса закрывает
соединения. Файлы, которые вы изменили сами, при удалении сохраняются.

Если ставили в другую папку, добавляйте к командам тот же `--install-dir`.

## Если что-то не работает

**Не найден Python venv.** На Debian/Ubuntu обычно нужен пакет `python3-venv`.
Установщик не запускает установку системных пакетов за вас.

**Порт занят.** Укажите другой порт при установке. Другие процессы не останавливаются.

**Сервис не запускается.** Посмотрите журнал:

```bash
journalctl --user -u zen-rate-gateway -n 30 --no-pager
```

Если ставили от root, уберите `--user`. У обычного пользователя сервис зависит
от его пользовательского systemd; запуск без входа в систему требует отдельной
настройки lingering. Установщик её сам не включает.

**Прокси не работает.** Проверьте логин, пароль и доступность прокси. Если все
маршруты недоступны, вернётся `502`; если все на паузе — `429`.

**Уже есть старая установка.** Не удаляйте её вслепую. Этот установщик не
переносит автоматически старые скрипты и сервисы, установленные вручную.
Сначала остановите старую версию, сохраните её настройки и уберите конфликтующие
файлы сами.

## Где лежат файлы

По умолчанию:

| Что | Где |
| --- | --- |
| Прокси и локальный ключ | `~/.config/opencode-zen-rotator/config.json` |
| Плагин | `~/.config/opencode/plugins/zen-rotation/index.ts` |
| Команда запуска | `~/.local/bin/opencode-zen` |
| Версии программы, копии файлов | `~/.local/share/opencode-zen-rotator/` |

Учитываются `XDG_CONFIG_HOME` и `XDG_DATA_HOME`. Список прокси можно передать
из своего локального файла через `--routes-file`; формат есть в
[`examples/proxies.example.json`](../examples/proxies.example.json).

## Тесты

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest --cov=zen_rotator --cov=install --cov-report=term-missing
node tests/test_plugin.mjs
```

Node.js нужен только для теста плагина. Обычные тесты не отправляют запросы
в Zen и не используют настоящие прокси. В CI есть проверка на Python 3.10–3.12.

## Безопасность

Не коммитьте свои прокси, токены, OpenCode-конфиги и логи. Прокси видит ваш
внешний трафик, поэтому не используйте случайные чужие адреса. Данные до Zen
передаются по HTTPS с проверкой сертификата.

Gateway слушает только `127.0.0.1`. Плагин добавляет локальный ключ, чтобы
посторонний локальный запрос не мог просто так пользоваться вашими прокси.
Ключ не заменяет безопасность самой машины. Плагин и конфиг доступны только
владельцу файлов. Подробнее — [SECURITY.md](../SECURITY.md).
